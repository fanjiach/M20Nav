# 4.3 机器狗控制模块（双机型兼容）
## 4.3.0 模块设计目标
机器狗控制模块作为上位机与底层机器狗硬件的核心交互层，需实现以下核心目标：
1. **协议透明化**：封装绝影X30（ROS+UDP）、山猫M20（ROS2+TCP/UDP+ASDU）的协议差异，向上层模块提供统一的控制接口，无需关注机型细节；
2. **指令高可靠**：指令下发超时重试、幂等性校验、状态前置校验，保障指令执行成功率≥99.9%；
3. **状态实时性**：10Hz高频采集机器狗运动/姿态/电量状态，延迟≤100ms；
4. **应急优先级**：急停/返航指令优先级最高，可中断所有非应急指令，响应延迟≤50ms；
5. **兼容性扩展**：预留机型适配接口，新增机型时仅需实现适配层，无侵入式扩展。

## 4.3.1 双机型适配整体架构
采用“抽象接口+机型适配层+通用逻辑层”的分层设计，架构如下：
```
上层模块（任务管理/手动遥控/自动返航）
        ↓
通用控制接口（MachineDogController）
        ↓
┌───────────────┬───────────────┐
│ X30适配层     │ M20适配层     │
│（ROS+UDP）    │（ROS2+TCP/UDP）│
└───────────────┴───────────────┘
        ↓
机器狗硬件（X30/M20）
```
- **通用控制接口**：定义标准化的控制方法（如`move_to_point`、`emergency_stop`、`get_status`），屏蔽机型差异；
- **机型适配层**：实现通用接口，完成指令格式转换、协议封装/解析、ROS/ROS2话题适配；
- **通用逻辑层**：处理指令重试、状态校验、幂等性控制等跨机型通用逻辑。

### 4.3.1.1 与任务管理模块的接口约定（必须对齐）
任务管理模块接收服务器下发的`route_json.point_ids`（点位编号数组），点位坐标由任务压缩包中的“地图路径json文件”提供。

机器狗控制模块需要满足以下最小约束：
1. 任务模块可按点位编号查点位并调用控制模块导航（推荐）；
2. 控制模块必须提供可被任务模块使用的“当前点位编号”（用于任务结束后返回“任务下发前的点位”）；
3. 控制模块对外统一返回“可解析的错误码/错误信息”，便于任务模块上报告警与任务失败原因。

#### 推荐调用链（当前任务模块实现兼容）
- 任务模块：从`/opt/robot/current_map_path.json`查到`point_id -> (x,y,z)`后调用 `move_to_point(point_id,x,y,timeout)`
- 控制模块：执行导航并更新内部状态缓存，`get_status()`返回`current_point_id`

### 4.3.1.2 机器狗状态字段标准（任务/通信模块依赖）
`get_status()`返回字典需至少包含：
- `online`：bool，是否在线（通信正常）
- `battery`：int，0~100
- `motion_state`：str，例如 idle/stand/nav/error
- `error_code`：int，0为无错误
- `error_msg`：str，可空
- `current_point_id`：str，当前所在点位编号（无法识别则为空）
- `pose`：可选，包含`x/y/z/yaw`（用于联调与定位）

### 4.3.1.3 坐标系与单位约定（必须明确）
地图路径json文件中`points[].coordinate=[x,y,z]`坐标系需要在项目内固定。建议采用：
- `map`坐标系（单位：米），与ROS/ROS2导航栈的`frame_id=map`一致；
- 若现场地图是经纬度，则需额外提供“经纬度→局部米制”的投影与原点参数，否则无法直接下发ROS导航目标。

### 4.3.2.2 UDP指令封装与解析规范
#### 4.3.2.2.1 指令头部结构（小端序）
| 字段          | 字节数 | 取值示例       | 说明                                   |
|---------------|--------|----------------|----------------------------------------|
| `code`        | 4      | 0x21040001（心跳） | 指令码（4字节小端）|
| `param_size`  | 2      | 0x0010（16字节）| 数据段长度（0~1024字节）|
| `type`        | 1      | 0x01（请求）| 0x01=请求，0x02=响应                   |
| `reserved`    | 1      | 0x00           | 预留扩展位                             |
| `req_id`      | 4      | 0x00000001     | 请求ID（用于回执匹配与幂等控制）       |
| `crc16`       | 2      | 0x5A8B         | 校验位（多项式0x8005，覆盖头部+数据段）|

#### 4.3.2.2.1.1 UDP包格式定义（实现必须遵循）
```
| code(4) | param_size(2) | type(1) | reserved(1) | req_id(4) | data(N) | crc16(2) |
```
约束：
1. `crc16`计算范围为：`code..req_id + data`（不包含crc16字段自身）；
2. `req_id`由上位机侧自增生成（重发同一条命令时req_id保持不变）；
3. X30响应包：`type=0x02`，`req_id`与请求一致，用于匹配回执。

#### 4.3.2.2.2 核心指令数据段格式
| 指令名称 | 指令码       | 数据段字段（键值对/字节序）| 示例数据段（16进制）|
|----------|--------------|-------------------------------------------|----------------------|
| 心跳     | 0x21040001   | `dog_id(4字节)` + `timestamp(8字节)`      | 00 00 00 01 5F 8A ...|
| 起立/趴下 | 0x21010202   | `action(1字节)` + `reserved(7字节)`       | 01 00 00 00 00 00 00 00 |
| 开始运动  | 0x21010201   | `gait_type(1字节)` + `speed(2字节)` + 预留 | 01 00 C8 00 00 00 00 00 |

#### 4.3.2.2.3 代码示例：UDP指令封装
```python
import struct
import crcmod

# 初始化CRC16校验器（多项式0x8005）
crc16_func = crcmod.mkCrcFun(0x18005, rev=True, initCrc=0x0000, xorOut=0x0000)

def pack_x30_udp_command(code: int, req_id: int, data: bytes, cmd_type: int = 0x01) -> bytes:
    """
    封装X30 UDP指令包
    :param code: 指令码（如0x21040001）
    :param req_id: 请求ID（回执匹配/幂等）
    :param data: 数据段字节
    :param cmd_type: 指令类型（0x01请求，0x02响应）
    :return: 完整UDP数据包
    """
    # 指令码（4字节小端）
    code_bytes = struct.pack("<I", code)
    # 数据段长度（2字节小端）
    param_size = struct.pack("<H", len(data))
    # 类型+预留（各1字节）
    type_reserved = struct.pack("<BB", cmd_type, 0x00)
    # 请求ID（4字节小端）
    req_id_bytes = struct.pack("<I", req_id)
    # 拼接头部
    header = code_bytes + param_size + type_reserved + req_id_bytes
    # 计算CRC16（头部+数据段）
    crc16 = struct.pack("<H", crc16_func(header + data))
    # 完整包 = 头部 + 数据段 + CRC16
    return header + data + crc16

# 示例：封装心跳指令
heartbeat_data = struct.pack("<Iq", 0x0001, 1715600000)  # dog_id=1, timestamp=1715600000
udp_packet = pack_x30_udp_command(0x21040001, 1, heartbeat_data)
print(f"X30心跳UDP包：{udp_packet.hex()}")
```

### 4.3.2.3 ROS话题通信细节
#### 4.3.2.3.1 导航目标点下发（/move_base/PoseStamped）
- 消息类型：`geometry_msgs/PoseStamped`
- 关键字段：
  | 字段路径                | 说明                          | 取值示例                  |
  |-------------------------|-------------------------------|---------------------------|
  | header.frame_id         | 坐标系                        | "map"                     |
  | header.stamp            | 时间戳                        | rospy.Time.now()          |
  | pose.position.x/y/z     | 目标点坐标（单位：米）| x=10.5, y=5.2, z=0.0      |
  | pose.orientation.w      | 朝向（四元数）| 1.0（水平朝前）|
- 代码示例：
```python
import rospy
from geometry_msgs.msg import PoseStamped

class X30NavController:
    def __init__(self):
        self.nav_pub = rospy.Publisher("/move_base/PoseStamped", PoseStamped, queue_size=10)
        rospy.init_node("x30_nav_controller", anonymous=True)

    def send_nav_point(self, point_id: str, x: float, y: float, timeout: int = 3):
        """
        下发X30导航点
        :param point_id: 路径点ID（如P001）
        :param x/y: 坐标
        :param timeout: 超时时间（秒）
        """
        # 前置校验：机器狗在线且姿态正常
        if not self._check_dog_status():
            raise RuntimeError("X30姿态异常，禁止下发导航指令")
        
        msg = PoseStamped()
        msg.header.frame_id = "map"
        msg.header.stamp = rospy.Time.now()
        msg.pose.position.x = x
        msg.pose.position.y = y
        msg.pose.position.z = 0.0
        msg.pose.orientation.w = 1.0

        # 超时重试（3次）
        for _ in range(3):
            self.nav_pub.publish(msg)
            rospy.sleep(0.1)
            # 检查是否到达目标（简化逻辑，实际需订阅状态）
            if self._check_reach_point(point_id):
                return True
        raise TimeoutError(f"X30导航点{point_id}下发超时")

    def _check_dog_status(self) -> bool:
        """校验机器狗在线+姿态正常"""
        # 实际需订阅/robot_status话题获取状态
        return True

    def _check_reach_point(self, point_id: str) -> bool:
        """校验是否到达目标点"""
        return False
```

#### 4.3.2.3.2 话题名与到点判定（必须补齐）
由于现场导航栈可能不同，导航目标发布与到点判定必须配置化，并明确判定口径：
- 目标发布话题（示例值，需按现场确认）：`/move_base_simple/goal` 或 `/move_base/PoseStamped`
- 到点判定方式（二选一或组合）：
  1. 订阅导航结果（action result 或状态话题），以“状态=SUCCEEDED”判定到点
  2. 订阅机器人定位（如`/amcl_pose`）并以距离阈值判定：`distance(current, target) <= 0.3m`持续`>=1s`

建议在文档中补充：目标点的朝向字段与机器人实际到点判定是否依赖朝向（yaw阈值）。

| 异常类型               | 触发条件                          | 处理策略                                                                 |
|------------------------|-----------------------------------|--------------------------------------------------------------------------|
| UDP连接超时            | 指令下发3s未收到回执              | 重试3次，仍失败则标记“X30通信异常”（错误码1001），上报Level 2告警         |

## 4.3.3 山猫M20（ROS2 Humble + TCP/UDP + ASDU）深度设计
### 4.3.3.1 通信拓扑
| 通信通道       | 目标地址/端口       | 通信方向       | 用途                  | 传输特性                     |
|----------------|---------------------|----------------|-----------------------|------------------------------|
| TCP长连接      | 10.21.31.103:30001  | 双向           | 大指令/ASDU报文传输   | 可靠连接、保活10s、重连间隔5s |
| UDP短指令通道  | 10.21.31.103:30000  | 上位机→M20     | 心跳/急停/速度指令    | 低延迟、重试3次              |
| ROS2导航话题   | /NAV_CMD            | 上位机→M20     | 导航任务下发          | QoS：RELIABLE，历史保留10条  |
| ROS2状态话题   | /MOTION_STATE       | M20→上位机     | 运动状态上报          | QoS：VOLATILE，10Hz发布      |

### 4.3.3.2 ASDU报文规范（TCP/UDP通用）
#### 4.3.3.2.1 固定头部（16字节）
| 偏移量 | 字节数 | 字段         | 取值/说明                                  |
|--------|--------|--------------|--------------------------------------------|
| 0-3    | 4      | magic        | 0xeb91eb90（魔数，帧识别）|
| 4-7    | 4      | length       | 数据段长度（网络字节序，0~2048）|
| 8-11   | 4      | msg_id       | 报文ID（唯一，用于回执匹配，0~0xFFFFFFFF） |
| 12-13  | 2      | format       | 0x0100（JSON格式+保留位）|
| 14-15  | 2      | reserved     | 0x0000（预留）|

#### 4.3.3.2.1.1 TCP粘包拆包规则（实现必须遵循）
1. 先读满16字节头部；
2. 解析`length`得到数据段长度N（不包含头部长度）；
3. 循环读取直到拿到N字节数据段；
4. 将`data`按UTF-8解码为JSON并解析。

否则会在高并发与网络抖动时出现“读到半包/多包”导致JSON解析失败。

#### 4.3.3.2.2 ASDU数据段（JSON格式）
核心字段规范：
| 必选字段       | 类型   | 说明                                  |
|----------------|--------|---------------------------------------|
| `cmd`          | string | 指令类型（如"motion_state"、"nav_task"） |
| `param`        | object | 指令参数（键值对）|
| `timestamp`    | int64  | 时间戳（毫秒）|
| `dog_id`       | string | 机器狗标识（如M20_002）|

#### 4.3.3.2.3 代码示例：ASDU报文封装与发送
```python
import json
import struct
import socket

class M20ASDUController:
    def __init__(self, tcp_host: str = "10.21.31.103", tcp_port: int = 30001):
        self.tcp_sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
        self.tcp_sock.settimeout(10)
        self.tcp_sock.connect((tcp_host, tcp_port))
        self.msg_id = 0  # 报文ID自增

    def pack_asdu(self, cmd: str, param: dict) -> bytes:
        """封装M20 ASDU报文"""
        # 数据段JSON
        data = {
            "cmd": cmd,
            "param": param,
            "timestamp": int(time.time() * 1000),
            "dog_id": "M20_002"
        }
        data_bytes = json.dumps(data, ensure_ascii=False).encode("utf-8")
        # 固定头部
        magic = struct.pack("<I", 0xeb91eb90)
        length = struct.pack(">I", len(data_bytes))  # 网络字节序
        msg_id = struct.pack(">I", self.msg_id)
        self.msg_id += 1
        format_field = struct.pack(">H", 0x0100)
        reserved = struct.pack(">H", 0x0000)
        # 拼接头部+数据段
        header = magic + length + msg_id + format_field + reserved
        return header + data_bytes

    def send_tcp_asdu(self, cmd: str, param: dict) -> dict:
        """发送TCP ASDU指令并等待回执"""
        packet = self.pack_asdu(cmd, param)
        self.tcp_sock.send(packet)
        # 接收回执（必须按16字节头+length拆包）
        header = self.tcp_sock.recv(16)
        length = struct.unpack(">I", header[4:8])[0]
        buf = b""
        while len(buf) < length:
            buf += self.tcp_sock.recv(length - len(buf))
        resp_data = json.loads(buf.decode("utf-8"))
        if resp_data.get("result") != "success":
            raise RuntimeError(f"M20指令{cmd}执行失败：{resp_data.get('error_msg')}")
        return resp_data

# 示例：下发M20导航任务
if __name__ == "__main__":
    m20_ctrl = M20ASDUController()
    nav_param = {
        "point_id": "P008",
        "x": 15.3,
        "y": 8.7,
        "timeout": 3000  # 超时3秒
    }
    resp = m20_ctrl.send_tcp_asdu("nav_task", nav_param)
    print(f"导航指令回执：{resp}")
```

### 4.3.3.3 ROS2话题通信细节
#### 4.3.3.3.1 QoS配置（关键）
M20 ROS2通信采用严格的QoS配置，保障不同场景下的传输可靠性：
| 话题名称       | QoS配置类型       | 可靠性   | 历史保留 | 有效期   | 适用场景          |
|----------------|-------------------|----------|----------|----------|-------------------|
| /NAV_CMD       | RELIABLE          | 可靠     | 10条     | 5s       | 导航任务下发      |

| /GAIT          | RELIABLE          | 可靠     | 5条      | 3s       | 步态切换指令      |

#### 4.3.3.3.2 速度指令下发（/NAV_CMD）

### 4.3.3.4 状态采集与解析
M20状态通过“TCP ASDU回执+ROS2话题订阅”采集，字段映射如下：

### 4.3.3.5 异常处理规则
| 异常类型               | 触发条件                          | 处理策略                                                                 |
|------------------------|-----------------------------------|--------------------------------------------------------------------------|
| TCP连接断开            | 保活包10s未响应                   | 自动重连（间隔5s），3次失败则切换UDP通道，上报Level 2告警（错误码1002）|
| ASDU报文解析失败       | JSON格式错误/字段缺失             | 丢弃报文，返回错误回执，记录解析失败日志，触发Level 1告警                |
| ROS2话题发布失败       | /NAV_CMD发布超时                  | 降级为TCP ASDU下发导航指令，失败则触发手动遥控模式                      |
| 充电桩对接指令失败     | ASDU返回错误码7001                | 切换备用充电桩，重新规划路径，3次失败则上报Level 3告警                  |

## 4.3.4 通用控制适配层设计（核心）
### 4.3.4.1 抽象接口定义
```python
from abc import ABC, abstractmethod
from typing import Dict, Any, Optional

class BaseMachineDogController(ABC):
    """机器狗控制抽象接口"""
    @abstractmethod
    def emergency_stop(self) -> bool:
        """紧急急停（优先级最高）"""
        pass

    @abstractmethod
    def return_home(self, target_pile: str = "CP001") -> bool:
        """触发自动返航"""
        pass

    @abstractmethod
    def move_to_point(self, point_id: str, x: float, y: float, timeout: int = 3) -> bool:
        """下发导航点"""
        pass

    @abstractmethod
    def set_motion_state(self, state: str, param: Dict[str, Any]) -> bool:
        """设置运动状态（起立/趴下/步态切换）"""
        pass

    @abstractmethod
    def get_status(self) -> Dict[str, Any]:
        """获取机器狗实时状态"""
        pass

    @abstractmethod
    def check_online(self) -> bool:
        """校验机器狗是否在线"""
        pass
```

### 4.3.4.4 通用错误码建议（上层可统一处理）
建议将机型侧错误码映射到统一语义，避免上层逻辑分叉：
- 1001：通信超时/无回执
- 1002：连接断开/重连失败
- 1003：指令被拒绝（姿态/安全限制）
- 1004：导航失败/超时
- 1005：状态采集中断

### 4.3.4.5 依赖与运行环境约束（建议补齐）
- X30：ROS Noetic（rospy）、UDP socket；CRC16计算库（`crcmod`或自实现）
- M20：ROS2 Humble（rclpy）、TCP/UDP socket；ASDU拆包必须实现
- 上位机运行环境需明确：
  - 运行在哪台工控机（IP/网卡/路由）
  - ROS/ROS2节点启动方式（systemd/roslaunch/colcon）
  - 配置文件位置（IP/端口/话题名/超时参数）

### 4.3.4.2 机型适配工厂
通过工厂模式实现机型自动适配，上层模块仅需指定`dog_type`即可初始化对应控制器：
```python
class MachineDogControllerFactory:
    @staticmethod
    def create_controller(dog_type: str, dog_id: str) -> BaseMachineDogController:
        """
        创建机器狗控制器
        :param dog_type: "X30" / "M20"
        :param dog_id: 机器狗标识（如X30_001）
        :return: 对应机型的控制器实例
        """
        if dog_type == "X30":
            return X30Controller(dog_id)
        elif dog_type == "M20":
            return M20Controller(dog_id)
        else:
            raise ValueError(f"不支持的机型：{dog_type}")

# 上层模块调用示例
if __name__ == "__main__":
    # 初始化X30控制器
    x30_ctrl = MachineDogControllerFactory.create_controller("X30", "X30_001")
    # 通用接口调用（无需关注机型）
    x30_ctrl.emergency_stop()
    status = x30_ctrl.get_status()
    print(f"X30状态：{status}")

    # 初始化M20控制器
    m20_ctrl = MachineDogControllerFactory.create_controller("M20", "M20_002")
    m20_ctrl.move_to_point("P008", 15.3, 8.7)
```

### 4.3.4.3 指令生命周期管理
所有指令遵循统一的生命周期流程，保障执行可靠性：
```
指令下发前校验 → 指令封装 → 发送（TCP/UDP/ROS） → 等待回执 → 结果解析 → 异常重试 → 状态更新
```
#### 关键环节说明：
1. **前置校验**：下发指令前必须校验机器狗在线状态、姿态状态、电量状态，任一不满足则拒绝下发；
2. **幂等性控制**：3s内重复下发的相同指令（如同一导航点），直接返回上次执行结果，避免重复执行；
3. **超时重试**：指令超时未回执则重试3次，重试间隔依次为500ms、1000ms、1500ms；
4. **结果回调**：指令执行完成后，同步更新本地状态缓存，触发状态变更回调（如任务管理模块）。

## 4.3.6 性能优化策略
1. **指令批量下发**：连续导航点采用批量封装下发（X30 UDP合并包/M20 ASDU批量指令），减少通信次数；
2. **状态缓存复用**：100ms内重复获取状态时，直接返回缓存值，降低机器狗通信压力；
3. **协议轻量化**：非核心指令采用UDP传输，核心指令采用TCP可靠传输，平衡延迟与可靠性；
4. **硬件加速**：ROS/ROS2话题发布/订阅采用多线程异步处理，避免主线程阻塞；
5. **异常预判**：基于历史状态数据预判机器狗异常（如电量骤降），提前触发保护机制。

## 4.3.7 扩展与维护
1. **新增机型适配**：新增机型时，仅需实现`BaseMachineDogController`抽象接口，无需修改上层逻辑；
2. **协议版本升级**：预留协议版本字段（如ASDU头部新增version字段），支持协议平滑升级；
3. **日志埋点**：所有指令/状态交互记录结构化日志（包含指令ID、执行时长、结果），便于问题定位；
4. **配置化管理**：机型通信参数（IP/端口/超时时间）通过配置文件管理，支持热更新。
