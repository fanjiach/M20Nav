# 机场廊桥巡检机器狗上位机程序开发技术文档

## 1. 文档概述

### 1.1 项目背景

基于**绝影X30/M20机器狗**开发自动巡检系统，通过上位机实现**服务器指令实时接收、机器狗控制、任务自动化执行、数据回传、版本同步**等核心能力，替代人工完成廊桥标准化巡检，提升巡检效率与安全性，降低人工成本。

### 1.2 开发目的

- 实现服务器↔上位机**双向实时通信**，无延迟下发指令、上报状态，保障指令传输可靠性
- 完成机器狗**导航巡检、模型识别、视频缓存、异常上报**全流程自动化，覆盖廊桥巡检核心场景
- 保障程序/地图**版本一致性**、系统**时间同步**、多机路段**互斥执行**，避免执行冲突与版本异常
- 兼容绝影X30（ROS+UDP）、M20（ROS2+TCP/UDP）双机型通信协议，降低机型适配成本
- 提供**手动/自动双模切换**、紧急情况**自动返航**能力，提升系统容错性与应急处置能力

### 1.3 适用范围

- 上位机：机器狗机载工控机/外接上位机
- 受控设备：绝影X30、山猫M20机器狗
- 通信对象：云端服务器（WebSocket）、机器狗运动/感知/导航主机
- 业务场景：机场廊桥自动巡检、异常告警、数据回传、应急处置

## 3. 系统架构

### 3.1 整体架构

采用**分层模块化设计**，WebSocket作为核心通信通道，低耦合高内聚，各模块独立部署与扩展：

```
云端服务器 ←WebSocket长连接→ 服务器通信模块 ←→ 任务管理模块
                                                      ↓
机器狗控制模块 ← 视频处理模块 ← 版本同步模块 ← 异常处理模块
                                                      ↓
自动返航模块 ←→ 手动遥控模块 ←→ 模型识别模块
```

## 4. 核心功能模块设计

### 4.1 WebSocket服务器通信模块

#### 4.1.1 通信规范

- 协议：**WebSocket**（实时指令）、**HTTP/HTTPS**（文件传输）、**UDP**（心跳/状态上报）
- 通信模式：**双向全双工**，服务器可主动下发指令，上位机实时上报状态
- 数据格式：**JSON**，字符编码UTF-8，大消息（＞1024字节）采用gzip压缩
- 连接机制：自动重连（失败间隔1s、3s、5s、10s递增，最大10s），3s心跳保活，服务器应在1s内返回`heartbeat_ack`；连续2次未收到回执即标记通信异常并进入重连
- 文件传输：WebSocket传输文件URL/MD5，上位机通过HTTP/HTTPS异步下载（断点续传Range）、下载速度≤1MB/s、下载完成后分段MD5（每1MB）+整体MD5校验
- 安全机制：连接时通过`Authorization: Bearer {token}`身份校验，核心指令采用AES-128-CBC加密（当前实现覆盖`remote_control`，其余类型可按相同模式扩展），消息防重放（timestamp+nonce），核心指令可携带`sign`

#### 4.1.1.1 任务包与地图文件说明（实现约定）
- 服务器下发的`zip_url`指向任务压缩包（zip），压缩包包含“地图文件夹 + 地图路径json文件”
- 上位机下载并解压后，将地图文件夹复制到机器狗指定目录，并通过Linux软链接切换为“当前地图”
- 地图路径json文件为人工配置，包含该地图可到达点位与线段信息；上位机执行任务时，通过任务下发的点位编号数组在该文件中查找点位详情
- 地图路径json文件推荐采用标准结构（points+segments+home_point_id），用于点位查找与线段端点合法性校验，规范定义见：[任务管理模块.md:4.2.2.5](file:///e:/CH-HCNetSDKV6.1.9.48_build20230410_win64_20251013160408/demo/M20Nav/文档相关/上位机/任务管理模块.md#L63-L114)

#### 4.1.2 消息类型（固定字段：`msg_type`）

| msg\_type        | 功能           | 通信方向    | 补充字段                                                                                      |
| ---------------- | ------------ | ------- | ----------------------------------------------------------------------------------------- |
| `heartbeat`      | 3s心跳、状态上报    | 上位机→服务器 | battery（电量）、motion\_state（运动状态）、error\_code（错误码）、seq\_id（消息序列号）                           |
| `heartbeat_ack`  | 心跳回执         | 服务器→上位机 | seq\_id（与心跳一致）、server\_time（服务器时间）                                                          |
| `task_push`      | 服务器主动下发任务    | 服务器→上位机 | task\_id、execute\_time、task\_type、route\_json、zip\_url、map\_md5、priority（优先级）             |
| `task_pause`     | 暂停正在执行的任务    | 服务器→上位机 | task\_id、pause\_reason、operator（操作人）                                                      |
| `task_cancel`    | 取消未执行/执行中的任务 | 服务器→上位机 | task\_id、cancel\_reason、operator                                                          |
| `task_ack`       | 任务指令回执       | 上位机→服务器 | task\_id、ack\_result（success/fail）、error\_code                                              |
| `version_check`  | 程序/地图版本校验    | 双向      | program\_md5、map\_md5、version\_url、update\_type（全量/增量）                                    |
| `version_ack`    | 版本校验回执       | 双向      | check\_result（match/mismatch）、version\_url、update\_size                                      |
| `time_sync`      | 时间同步         | 双向      | server\_time、local\_time、offset（时差）、sync\_result（同步结果）                                    |
| `section_check`  | 导航路段占用校验     | 双向      | section\_id、dog\_id、occupy\_status（占用状态）、timeout（等待超时）                                    |
| `result_upload`  | 任务执行结果上报     | 上位机→服务器 | task\_id、execute\_result、complete\_rate、execute\_duration、error\_detail                   |
| `alarm_upload`   | 异常告警+视频通知    | 上位机→服务器 | alarm\_level（告警等级）、alarm\_msg、video\_url、snapshot\_url、confidence（识别置信度）                  |
| `connect_ack`    | 连接建立回执       | 服务器→上位机 | connect\_time、server\_version、max\_retry（最大重连间隔）                                          |
| `remote_control` | 手动遥控指令下发     | 服务器→上位机 | control\_type、control\_param（速度/角度）、valid\_time（指令有效期）                                    |
| `remote_ack`     | 遥控指令回执       | 上位机→服务器 | control\_type、ack\_result、execute\_time（ms）                                                 |
| `return_home`    | 返航指令/状态上报    | 双向      | return\_reason、home\_status、battery\_threshold、target\_charging\_pile、backup\_pile（备用充电桩） |
| `disconnect`     | 主动断开通知       | 上位机→服务器 | disconnect\_reason、local\_time                                                              |
| `emergency_stop` | 急停指令/状态      | 双向      | stop\_reason、operator、sign                                                                  |
| `file_upload`    | 文件上传通知       | 上位机→服务器 | file\_type、file\_url、file\_md5、file\_size                                                  |
| `file_ack`       | 文件校验回执       | 服务器→上位机 | file\_url、check\_result、error\_code                                                         |

### 4.2 任务管理模块

#### 4.2.1 任务流程

1. WebSocket实时接收服务器任务（压缩包URL、执行时间、任务类型、路线JSON、任务优先级），校验消息完整性（seq\_id去重）
2. 任务入库（本地sqlite），按优先级排序，异步下载压缩包→校验（失败则重新下载，最大重试3次）→解压→替换机器狗导航地图
3. 解析路线JSON→生成路径点队列（包含路径点ID、坐标、停留时间、检测类型、路段ID），预校验路径点合法性
4. 定时触发任务→前置校验（版本/时间/机器狗状态/网络状态）→按路径点依次下发，下发前校验路段占用状态
5. WebSocket实时校验路段占用→执行导航→实时上报执行进度（每完成1个路径点上报1次）
6. 任务暂停/取消：接收服务器指令，立即停止当前路径点执行，释放路段占用，上报暂停/取消状态
7. 任务完成/异常→WebSocket实时回传结果（完成率、执行时长、异常信息），异常任务支持断点续跑

#### 4.2.2 路径点互斥机制

- 下发路径点前，预先遍历后续4个路径点，提取路段ID，路段用tag来区分可占用路段和不可占用路段，如果后续路段有可占用路段，则通过WebSocket实时请求服务器：`是否有其他机器狗占用该路段`
- 占用则等待（1s轮询，最大等待30s，超时则触发Level 2异常），未占用则下发导航指令并标记路段占用（携带dog\_id与时间戳）
- 路径点执行完成/异常中断→实时释放路段，释放指令超时未回执则重复发送（3次），避免死锁

#### 4.2.3 任务优先级规则

| 优先级   | 任务类型      | 执行规则                                 | 补充说明                       |
| ----- | --------- | ------------------------------------ | -------------------------- |
| 1（最高） | 紧急返航/急停   | 立即中断当前任务，优先执行，禁止被其他任务中断              | 急停指令优先级高于返航                |
| 2     | 手动遥控      | 暂停自动巡检任务，响应遥控指令，遥控超时（5s）自动恢复原任务      | 仅在遥控指令有效期内保持优先级            |
| 3     | 实时巡检任务    | 按执行时间执行，可暂停低优先级任务，支持任务插队             | 服务器可手动调整优先级                |
| 4     | 定时巡检任务    | 基础优先级，可被高优先级任务中断，中断后断点续跑             | 定时任务可批量配置执行窗口              |
| 5（最低） | 版本更新/数据同步 | 空闲时执行（无其他任务运行时），不影响核心业务，可被任意高优先级任务中断 | 版本更新完成后需重启服务的，标记重启时间并通知服务器 |

### 4.3 机器狗控制模块（双机型兼容）

#### 4.3.1 绝影X30（ROS+UDP）

- 通信：UDP `192.168.1.103:43893` + ROS Noetic，UDP连接超时时间3s，超时重试
- 核心指令（匹配X30接口文档）：
  | 指令    | 指令码           | ROS话题                   | 说明                    | 超时重试次数 |
  | ----- | ------------- | ----------------------- | --------------------- | ------ |
  | 心跳    | 0x21040001    | -                       | ≥2Hz保活，丢失3次心跳则标记机器狗失联 | -      |
  | 起立/趴下 | 0x21010202    | -                       | 状态切换，运动中禁止下发          | 3      |
  | 开始运动  | 0x21010201    | -                       | 进入踏步，需先校验机器狗姿态        | 3      |
  | 导航目标  | -             | /move\_base/PoseStamped | 下发导航点，附带路径点ID与超时时间    | 3      |
  | 状态上报  | 0x1008/0x1009 | -                       | 运行/运动状态，上报频率10Hz      | -      |
- 格式：UDP小端`CommandHead(code, size, type)` + 数据段 + CRC16校验位，接收端校验失败则丢弃并反馈

#### 4.3.2 山猫M20（ROS2+TCP/UDP+ASDU）

- 通信：
  - TCP：`10.21.31.103:30001`（长连接，保活时间10s）
  - UDP：`10.21.31.103:30000`（短指令，超时时间3s）
  - ROS2 Humble（话题通信，QoS等级：可靠传输）
- 核心指令（匹配M20手册「1.2控制类ASDU、2.2 ROS2话题」）：
  | 指令   | Type/Command       | ROS2话题         | 说明                     | 超时重试次数 |
  | ---- | ------------------ | -------------- | ---------------------- | ------ |
  | 心跳   | Type=100, Cmd=100  | -              | ≥1Hz保活，丢失5次心跳则标记机器狗失联  | -      |
  | 运动状态 | Type=2, Cmd=22     | /MOTION\_STATE | 站立/趴下/RL，下发前校验当前状态     | 3      |
  | 步态   | Type=2, Cmd=23     | /GAIT          | 平地/楼梯步态，自动适配导航路径地形     | 3      |
  | 导航任务 | Type=1003, Cmd=1   | /NAV\_CMD      | 单点导航，附带路径点ID与超时时间      | 3      |
  | 速度指令 | -                  | /NAV\_CMD      | x/y/wz速度，自动限速（≤0.5m/s） | 3      |
  | 状态上报 | Type=1002, Cmd=4/6 | -              | 运控/基础状态，上报频率10Hz       | -      |
- 格式：16字节头（0xeb91eb90）+ JSON ASDU + 校验位，TCP/UDP通用，ASDU字段标准化

#### 4.3.3 通用控制规则

- 急停机制：接收急停指令（服务器/本地）→立即下发停止指令→切断运动控制通道→上报急停状态→5s内禁止下发运动指令
- 指令幂等性：重复下发相同指令（3s内）不重复执行，记录指令执行日志，避免机器狗异常
- 状态校验：下发指令前校验机器狗在线状态、姿态状态、电量状态，任一状态不满足则触发异常并拒绝下发
- 双机型适配层：封装统一的机器狗控制接口，上层模块无需关注机型差异，适配层自动转换指令格式

### 4.4 视频处理模块

- 采集：OpenCV读取机器狗前置/全景摄像头实时流（1080P/30fps），支持多摄像头冗余采集，摄像头故障自动切换备用摄像头
- 缓存：**环形队列**存储最近1分钟视频帧（内存缓存，单帧压缩至0.5MB），内存不足时自动切换至磁盘缓存（/tmp/视频缓存目录）
- 编码：实时H.264硬件编码，码率控制在2Mbps，帧率自适应（15-30fps），平衡画质与带宽
- 异常触发切片规则：
  | 触发类型   | 切片规则          | 压缩策略        |
  | ------ | ------------- | ----------- |
  | 机器狗报错  | 切片前10s+后20s视频 | 高压缩比（画质优先）  |
  | 导航失败   | 切片前15s+后15s视频 | 高压缩比（画质优先）  |
  | 视觉识别异常 | 切片前5s+后10s视频  | 平衡压缩（画质+速度） |
  | 手动触发   | 切片前30s+后30s视频 | 低压缩比（速度优先）  |
- 上传：切片完成后，先上传缩略图（320x240）→再异步上传完整视频（断点续传）→上传完成后通知服务器校验→校验通过删除本地临时文件，校验失败则重新上传（最大3次）

### 4.5 版本同步模块

- 同步时机：WebSocket连接建立、下载任务前、执行任务前、定时触发（每小时）、服务器主动指令、程序启动时
- 同步类型：
  | 同步类型 | 校验粒度                    | 更新策略                      | 回滚机制                      |
  | ---- | ----------------------- | ------------------------- | ------------------------- |
  | 程序版本 | 整体程序包MD5 + 关键模块MD5      | 全量更新，更新后重启服务，重启前通知服务器     | 更新失败自动回滚至更新前版本，记录回滚日志     |
  | 地图版本 | 地图文件MD5（按路段） + 整体地图包MD5 | 增量更新，仅替换变更路段地图，更新后校验导航可用性 | 地图加载失败则回滚至原地图，触发Level 1告警 |
  | 配置版本 | 配置文件MD5 + 字段级校验         | 热更新，无需重启服务，更新后立即生效        | 配置解析失败则使用默认配置，上报配置异常      |
- 同步流程：
  1. WebSocket请求版本信息（程序MD5/地图MD5/配置MD5），携带本地当前版本信息
  2. 本地对比→不符则通过URL异步下载更新包（断点续传，限速1MB/s避免占用带宽）
  3. MD5校验更新包（分段校验）→解压替换（程序/地图/配置），替换前备份原文件
  4. 热更新配置/重启服务→WebSocket上报更新完成（含新版本MD5+更新耗时）
  5. 回滚机制：更新失败（校验/解压/替换）则自动回滚至旧版本，上报更新异常（含失败原因）

### 4.6 异常处理模块

#### 4.6.1 异常分级

| 等级          | 定义                                   | 处理策略                              | 恢复机制                         |
| ----------- | ------------------------------------ | --------------------------------- | ---------------------------- |
| 警告（Level 1） | 非核心功能异常（如视频缓存不足、版本校验超时、单帧识别失败）       | 本地日志+WebSocket上报，不中断任务，记录异常上下文    | 自动重试（5s间隔，3次），无需人工介入         |
| 错误（Level 2） | 核心功能异常（如单个路径点导航失败、路段占用超时、视频切片失败）     | 中断当前路径点+视频切片+上报+重试执行（3次），释放当前路段占用 | 重试失败则跳过该路径点，继续执行后续任务，标记异常路径点 |
| 致命（Level 3） | 系统级异常（如WebSocket断开、机器狗失联、低电量≤20%、越界） | 立即停止任务+急停保护+视频切片+上报+触发返航，禁止自动恢复   | 需人工确认异常原因，手动恢复任务或重启服务        |

#### 4.6.2 异常处理流程

1. 系统运行中捕获异常→分级标记→本地结构化日志记录（含异常栈、时间、机器狗状态、网络状态、指令上下文）
2. Level 3异常触发机器狗紧急保护（急停/断电保护），禁止下发任何运动指令
3. 1s内通过WebSocket上报异常状态信息（等级、原因、错误码、上下文ID），上下文ID关联本地日志便于排查
4. 联动视频模块切片→上传视频/截图至服务器，携带异常上下文ID
5. 按等级执行恢复策略（重试/返航/人工介入），记录恢复过程日志
6. 异常恢复后，上报恢复状态，可手动/自动继续任务（断点续跑）

#### 4.6.3 错误码规范

| 错误码段      | 归属模块          | 示例（错误码-描述）                                    | 处理建议                        |
| --------- | ------------- | --------------------------------------------- | --------------------------- |
| 1000-1999 | 机器狗控制模块       | 1001-X30 UDP连接失败；1008-M20导航点识别失败；1099-机器狗姿态异常 | 检查机器狗网络/供电/姿态，重启机器狗通信模块     |
| 2000-2999 | WebSocket通信模块 | 2001-连接超时；2005-心跳回执丢失；2099-消息解密失败             | 检查网络连接，重启WebSocket模块，校验加密密钥 |
| 3000-3999 | 任务管理模块        | 3001-路段占用超时；3005-任务解析失败；3099-路径点坐标非法          | 检查任务参数，协调路段占用，重新下发任务        |
| 4000-4999 | 视频处理模块        | 4001-摄像头采集失败；4005-视频切片编码错误；4099-视频上传超时        | 检查摄像头连接，重启视频模块，清理缓存目录       |
| 5000-5999 | 版本同步模块        | 5001-更新包MD5校验失败；5005-文件替换权限不足；5099-版本回滚失败     | 重新下载更新包，检查文件权限，手动回滚版本       |
| 6000-6999 | 模型识别模块        | 6001-ONNX模型加载失败；6005-识别置信度低；6099-推理超时         | 检查模型文件，调整推理参数，切换推理硬件        |
| 7000-7999 | 自动返航模块        | 7001-充电桩对接失败；7005-返航路径规划失败；7099-电量骤降          | 切换备用充电桩，手动遥控返航，检查电池状态       |

### 4.7 自动返航模块

#### 4.7.1 触发条件

- 低电量：电池电量≤20%（可配置，范围15%-25%），立即触发返航，上报Level 1告警
- 异常超时：Level 3异常未恢复超过60s（可配置），触发返航，上报Level 2告警
- 手动触发：服务器/本地下发返航指令，优先级最高，上报Level 1告警
- 越界保护：机器狗超出预设巡检区域，立即触发返航+急停，上报Level 3告警
- 路径规划：根据当前任务和当前路径点反向下发已执行路径点，实现原路返回；原路不可行则自动规划最优返航路径

#### 4.7.2 返航流程（新增）

1. 触发返航→立即停止当前任务→释放所有路段占用→上报返航开始状态
2. 规划返航路径（原路优先，备用路径兜底）→依次下发返航路径点，实时校验路径可用性
3. 导航至充电桩→尝试对接（最大重试3次）→对接成功则上报“返航完成”，进入充电状态
4. 对接失败→切换备用充电桩→重新规划路径，仍失败则上报Level 3告警，进入手动遥控模式

#### 4.7.3 容错机制

- 返航路径失败：自动切换备用充电桩，重新规划路径，记录路径失败原因
- 充电桩对接失败：上报异常（错误码7001），进入手动遥控模式，禁止自动重试对接
- 返航中电量骤降：就近寻找安全区域停靠，上报紧急告警（Level 3），触发急停保护
- 返航中断：返航过程中接收更高优先级指令（如急停），立即执行，中断返航，恢复后可继续返航

### 4.8 机器狗手动遥控模块

#### 4.8.1 遥控模式

- 本地遥控：通过上位机外接摇杆/键盘，直接下发控制指令（优先级最高），支持自定义按键映射
- 远程遥控：服务器WebSocket下发`remote_control`指令，上位机转发至机器狗，指令有效期5s
- 模式切换：自动/手动模式通过WebSocket指令/本地按键切换，切换时暂停当前任务，上报切换状态
- 视频回显：遥控模式下实时回显机器狗摄像头画面（延迟＜200ms），支持画面缩放与截图

#### 4.8.2 遥控指令规范

| 指令类型  | 参数范围          | 安全限制                                | 补充说明             |
| ----- | ------------- | ----------------------------------- | ---------------- |
| 前进/后退 | -0.5\~0.5 m/s | 速度＞0.5m/s自动限制为0.5m/s；运动中加速度≤0.2m/s² | 低电量（≤20%）禁止高速运动  |
| 左转/右转 | -90\~90 °/s   | 角速度＞90°/s自动限制为90°/s；转向时降速50%        | 楼梯步态下禁止大角度转向     |
| 起立/趴下 | 0（趴下）/1（起立）   | 运动中禁止下发，避免失衡；下发前校验机器狗姿态             | 姿态异常时拒绝下发        |
| 急停    | 无参数           | 立即生效，优先级最高；急停后需手动解除                 | 解除急停前校验机器狗状态     |
| 摄像头切换 | 0（前置）/1（全景）   | 实时切换，无延迟；切换失败则上报Level 1告警           | 支持默认摄像头自动恢复      |
| 步态切换  | 0（平地）/1（楼梯）   | 仅在静止状态下允许切换；切换后校验步态生效状态             | 楼梯步态下速度限制为0.3m/s |

#### 4.8.3 安全保护

- 遥控超时：无指令超过5s，自动停止运动，上报“遥控超时”状态，恢复至自动模式（如有未完成任务）
- 越界保护：超出预设巡检区域（电子围栏），自动停止并触发Level 2告警，禁止继续越界运动
- 速度限制：所有运动指令限速，加速度限制，避免机器狗失控；低电量时额外降速30%
- 硬件保护：外接摇杆/键盘故障时，自动禁用本地遥控，切换至远程遥控/自动模式

### 4.9 模型识别模块

#### 4.9.1 识别能力
  - 详见模型识别模块具体说明

#### 4.9.2 处理流程

1. 视频帧实时送入ONNX模型推理（10fps），推理前对帧进行预处理（降噪、缩放、归一化）

## 5. 通信协议规范

### 5.1 上位机 ↔ 服务器（WebSocket）（待商讨）

- 连接地址：`ws://服务器IP:端口/robot/{dog_id}`（非加密）；`wss://服务器IP:端口/robot/{dog_id}`（SSL加密）
- 重连机制：断开后自动重试，最大间隔10s，重连成功后补发离线期间关键消息（按seq\_id排序）
- 消息要求：所有消息必须携带`msg_type`、`dog_id`、`timestamp`、`seq_id`，可选携带`sign`（消息签名）
- 超时规则：心跳回执超时5s，标记通信异常；指令下发超时3s，触发重试（3次）；文件下载超时30s，断点续传
- 消息签名：核心指令（急停、返航、遥控）携带`sign`字段（MD5(dog\_id+timestamp+msg\_content+secret)），服务器校验签名合法性

### 5.2 上位机 ↔ 机器狗

#### 5.2.1 X30 UDP协议

- 目标地址：192.168.1.103:43893，本地绑定端口：随机（≥1024）
- 指令格式：`CommandHead(code, paramters_size, type)` + 数据段 + CRC16校验位，小端序
- 头部定义：
  | 字段              | 字节数 | 说明    | 取值范围                        |
  | --------------- | --- | ----- | --------------------------- |
  | code            | 2   | 指令码   | 0x01-心跳，0x02-运动控制，0x03-状态查询 |
  | paramters\_size | 2   | 数据段长度 | 0-1024字节                    |
  | type            | 1   | 指令类型  | 0x01-请求，0x02-响应             |
  | 保留位             | 1   | 预留扩展  | 0x00                        |
- 校验规则：指令尾部添加CRC16校验位（多项式0x8005），接收端校验失败则丢弃并反馈错误码

#### 5.2.2 M20 TCP/UDP协议

- 头部：16字节固定头部（0xeb 0x91 0xeb 0x90 + 长度 + 报文ID + 格式 + 保留位）
  | 偏移量   | 字节数 | 内容                  | 说明                 | 取值范围          |
  | ----- | --- | ------------------- | ------------------ | ------------- |
  | 0-3   | 4   | 0xeb 0x91 0xeb 0x90 | 魔数，用于帧识别           | 固定值           |
  | 4-7   | 4   | 长度                  | 后续数据段长度（网络字节序）     | 0-2048字节      |
  | 8-11  | 4   | 报文ID                | 唯一标识，用于回执匹配        | 0-0xFFFFFFFF  |
  | 12-13 | 2   | 格式                  | 0x01(JSON格式) + 保留位 | 0x0100-0x01FF |
  | 14-15 | 2   | 保留位                 | 预留扩展               | 0x0000        |
- 数据：JSON格式ASDU报文，字符编码UTF-8，字段标准化，必填字段：`cmd`、`param`、`timestamp`
- 回执机制：每个指令需返回对应报文ID的回执（成功/失败），超时未回执则重试（3次），重试失败标记指令执行失败

### 5.3 数据交互安全

- 身份校验：WebSocket连接时携带`dog_id+token`，token有效期7天，服务器校验合法性，非法连接立即断开
- 指令加密：核心指令（急停、遥控、返航）采用AES-128-CBC加密，密钥每24小时更新，通过安全通道下发
- 防重放：消息携带`timestamp`（精度1s）+`nonce`（随机数），服务器拒绝5s前的重复消息，nonce有效期5分钟
- 数据脱敏：上报数据中隐藏敏感信息（如服务器IP、认证信息），仅保留业务必要字段
- 传输加密：所有文件传输采用HTTPS，避免文件被篡改或窃取
