# 机器狗导航与打点控制程序技术文档

## 1. 概述
该程序是一个通过 TCP Socket 与机器狗进行通信的控制端脚本。主要功能包括：手动遥控机器狗记录路径点位（打点）、保存与读取路径数据（序列化为 `.pkl` 文件），以及控制机器狗按照预设点位进行自主导航、避障切换和自主充电。

- **服务端 IP**: `10.21.31.103`
- **服务端端口**: `30001`

## 2. 通讯协议说明
程序与机器狗的通信基于自定义的 TCP 二进制协议，每个数据包由 **16字节的协议头部** 和 **变长的 ASDU（应用服务数据单元）数据体** 组成。

### 2.1 协议头部 (16 Bytes)
| 字节偏移 | 字段名 | 长度 | 说明 |
| :--- | :--- | :--- | :--- |
| 0~3 | 起始标识 | 4 Bytes | 固定为 `0xeb 0x91 0xeb 0x90` |
| 4~5 | 数据长度 | 2 Bytes | ASDU 数据体的长度 (小端序) |
| 6~7 | 消息ID | 2 Bytes | 消息流水号 (小端序) |
| 8 | ASDU格式 | 1 Byte | `0x01` 表示 JSON 格式，`0x00` 为其他 |
| 9~15 | 预留 | 7 Bytes | 默认填充 0 |

### 2.2 ASDU 数据体
ASDU 数据体通常是一段 JSON 字符串，统一包裹在 `"PatrolDevice"` 根节点下。核心字段包含 `"Type"`（设备/指令类型）、`"Command"`（动作指令）、`"Time"` 和 `"Items"`（具体参数）。

## 3. 核心功能模块

### 3.1 协议封包与解包
- **`build_protocol_header`**: 构建 16 字节的请求头。
- **`parse_protocol_header`**: 解析 16 字节的响应头，验证起始标识并提取数据长度和格式。
- **`build_message`**: 将 JSON 字符串编码为 utf-8 字节流，并拼接生成的协议头，返回完整的待发送数据包。

### 3.2 网络通信
- **`receive_response`**: 分两步接收数据。先接收 16 字节头部，解析出数据体长度后，再接收对应长度的 ASDU 数据，并尝试将其反序列化为 Python 字典。
- **`send_and_receive_thread`**: 发送封包好的指令并等待机器狗返回响应，包含超时处理及日志打印功能。

### 3.3 业务功能函数
- **`record_point(client_sock, point_list)` (打点)**: 
  - 发送 `Type=1007, Command=2` 指令获取机器狗当前位姿坐标 `(PosX, PosY, PosZ, Yaw)`。
  - 会检查机器狗定位是否丢失 (`Location == 1`)。
  - 交互式询问用户当前点位地形（平地/楼梯）和方向（正向/逆向），并将完整点位信息存入列表。
- **`navigate_point(client_sock, point_list)` (导航)**:
  - 遍历点位列表，根据点位属性（是否是楼梯）自动切换避障模式 (`ObsMode`) 和导航模式 (`NavMode`)。
  - 发送 `Type=1003, Command=1` 下发单点导航任务，并循环等待机器狗返回成功状态码 (`ErrorCode == 8960`)。
  - 支持在导航结束的最后一个点位设置充电标志 (`PointInfo = 3`)。
- **`initiate_navigate(client_sock)` (初始化)**: 
  - 检查机器狗当前状态，若处于休眠 (`Sleep`)、充电 (`Charge`) 或趴下状态 (`MotionState`)，会自动调用相应指令使其恢复到可导航状态。
- **基础动作控制**:
  - `enter_charge` / `quit_charge`: 进入/退出充电 (`Type=2, Command=24`)。
  - `stand_up`: 起立 (`Type=2, Command=22`)。
  - `wake_up`: 唤醒 (`Type=1101, Command=6`)。

## 4. 程序运行流程
运行 `main()` 函数后，程序执行流程如下：
1. **建立连接**：通过 Socket 连接到机器狗服务端。
2. **模式选择**：
   - **模式 1 (打点模式)**：
     - 用户按回车键记录当前机器狗位置。
     - 输入 `q` 结束记录。
     - 提示输入导航名称，将记录的点位列表通过 `pickle` 序列化保存为 `<nav_name>.pkl` 文件。
   - **模式 2 (导航模式)**：
     - 提示用户输入要读取的导航记录文件名。
     - 通过 `pickle` 加载 `.pkl` 点位数据。
     - 调用 `navigate_point()` 依次引导机器狗前往目标点。

## 5. 异常与注意事项
- **网络稳定性**：接收响应默认超时时间为 5 秒（发送线程中等待 30 秒），需确保控制端与机器狗的网络连接稳定。
- **定位状态**：在打点时，若终端提示“定位丢失”，需根据机器狗手册流程重新进行定位初始化。
- **文件权限**：保存和读取 `.pkl` 文件时会在当前工作目录操作，若无读写权限会抛出 `PermissionError`，建议以管理员权限运行或更改工作在用户目录下放开在用户目录下。
